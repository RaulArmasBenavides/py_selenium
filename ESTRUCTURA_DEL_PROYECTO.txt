FLUJO DE EJECUCIÓN DE UN TEST
================================================================================

1. Usuario ejecuta:
   $ pytest stracon/modules/asignacion_formatos/test_asignacion_formatos.py -v

2. Pytest carga conftest.py:
   ✓ Fixture global (conftest.py raíz)
   ✓ Fixture de STRACON (stracon/conftest.py)

3. Test se ejecuta:
   ✓ Crea instancia de AsignacionFormatosPage
   ✓ AsignacionFormatosPage hereda de BasePage
   ✓ BasePage usa config.py para timeouts y Chrome options

4. Test interactúa con página:
   ✓ self.page.asignar_formato() → llama a métodos en pages.py
   ✓ pages.py usa métodos heredados de BasePage (click, fill, etc.)
   ✓ BasePage maneja waits automáticamente
   ✓ shared/logger.py registra acciones

5. Test verifica resultados:
   ✓ assert self.page.verificar_asignacion()
   ✓ Captura screenshot en caso de fallo

6. Driver se limpia:
   ✓ Fixture teardown cierra browser

================================================================================
CÓMO AGREGAR UN NUEVO MÓDULO
================================================================================

1️⃣  Crear carpeta:
    mkdir stracon/modules/nuevo_modulo

2️⃣  Crear pages.py (Page Objects):
    stracon/modules/nuevo_modulo/pages.py

    from pages.base_page import BasePage

    class NuevoModuloPage(BasePage):
        LOCATOR_1 = (By.ID, "elemento_1")

        def mi_accion(self):
            self.click(self.LOCATOR_1)

3️⃣  Crear test file:
    stracon/modules/nuevo_modulo/test_nuevo_modulo.py

    class TestNuevoModulo:
        def test_algo(self, stracon_driver):
            page = NuevoModuloPage(stracon_driver)
            page.mi_accion()

4️⃣  Ejecutar:
    $ pytest stracon/modules/nuevo_modulo/ -v

================================================================================
DIFERENCIA: Antes vs Después
================================================================================

❌ ANTES (Sin POM):
├── test_add_owner.py          # Selectores aquí
├── test_add_owner2.py         # DUPLICADO
├── test_add_owner_pet.py      # DUPLICADO
└── selenium_testcase.py       # Mezcla todo

Problemas:
- Mucho código duplicado
- Si cambia HTML, cambiar todos los tests
- No escalable
- Difícil de mantener

✅ DESPUÉS (Con POM):
├── pages/base_page.py         # Métodos comunes (una sola fuente)
├── stracon/modules/asignacion_formatos/
│   ├── pages.py               # Selectores AQUÍ (un solo lugar)
│   └── test_asignacion_formatos.py  # Tests limpios
└── stracon/modules/reportes/
    ├── pages.py               # Selectores para este módulo
    └── test_reportes.py       # Tests limpios

Ventajas:
- Código reutilizable (basepage.py)
- Un solo lugar para cambiar selectores
- Muy escalable (agregar módulos es trivial)
- Fácil de mantener
- Profesional (estándar en empresas)

================================================================================
COMANDOS RÁPIDOS
================================================================================

Activar entorno:
  .\env\Scripts\activate

Instalar dependencias:
  pip install -r requirements.txt

Ejecutar todos los tests:
  pytest stracon/ -v

Ejecutar un módulo:
  pytest stracon/modules/asignacion_formatos/ -v

Ejecutar un test específico:
  pytest stracon/modules/asignacion_formatos/test_asignacion_formatos.py::TestAsignacionFormatos::test_asignar_formato_exitoso

Con reportes:
  pytest stracon/ --html=report.html

Ejecutar en paralelo:
  pytest stracon/ -n auto

Ver logs:
  pytest stracon/ -v -s

Parar en primer fallo:
  pytest stracon/ -x

REFERENCIA: Métodos Base (base_page.py)

self.click(locator)               # Click con wait automático
